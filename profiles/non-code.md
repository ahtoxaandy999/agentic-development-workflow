# Non-code profile

Defaults for documents, research, operations or business work, with or
without Git. Copy the [template](template.md), start from these values, and
change what differs.

## Change unit and identity

- A document version: the file or folder plus a commit SHA under Git, or a
  version number and date without Git.
- Work in progress lives in a draft location; an accepted version is never
  edited in place. A new version is written beside it.
- Each change carries a short note: what changed and why, sources used, and
  what the reviewer should check.

## Evidence

- Every claim taken from outside names its source and the date it was read.
- Numbers name their source, date and unit; estimates are marked as such.
- Claims that cannot be sourced are listed as assumptions.

## Checks

| Tier | Typical content |
| --- | --- |
| `<check fast>` | links resolve, sources are cited, terms and names are consistent, spelling |
| `<check full>` | the fast check on the whole document plus a fresh-reader review |

## Review

- `<review channel>`: a review file next to the document version, or a pull
  request comment when under Git.
- The reviewer reads the exact version as a fresh reader and checks sources,
  claims, scope against the brief, and anything private that must not leave
  its boundary.

## External actions

These need the owner's yes for each action, never a standing permission:

- sending mail or messages, posting, publishing;
- contacting people or organizations;
- spending, signing up, accepting terms;
- sharing a document outside its current audience.

Agents prepare drafts and list the exact action; the owner sends.

## Data boundaries

- The profile names which data stays where (for example: client data never
  leaves the project folder, never goes to an outside service).
- Private content is never copied into prompts for outside services without
  the owner's yes for that service.

## Skills

`clarify-task`, `decision-split`, `verification-before-completion`,
`independent-review`, `handoff`, `workspace-closeout`; `status-digest` when
several sessions run.
