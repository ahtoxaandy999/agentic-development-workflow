## Selection rationale

The task-control reference is selected because it is both independently useful
to the accepted design and suitable as the first representative evidence case:

- TD-01 already selects one repository Markdown control record per future
  product task.
- TD-02 selects one execution-state recorder while keeping decision and
  evidence authorities distinct.
- TD-03 selects immutable contract/decision/event/evidence records plus one
  mutable current projection.
- TD-04 through TD-10 already define candidate identity, evidence, rehydration,
  supervised execution, recovery, dependency/join and gate semantics that the
  reference must explain.
- The tooling design explicitly says no operative schema or operational sample
  exists yet.
- A bounded annotated reference can expose ambiguity before any real task
  record, recorder or implementation is authorized.
- Its Markdown-only output gives RU-1 the documentation-oriented profile
  required by the representative-use scoping.

This selection does not rely on an unaccepted mechanism. It selects no product
repository or dogfooding target and requires no new research.
